# SOP: 任务收口与完成声明

> 本 SOP 负责判断一个实施任务是否真正闭环。创建文件、修改代码或跑过一条命令都
> 不是单独的完成依据；适用的产物、状态、证据和残余必须一起交代清楚。

## 触发条件

- Agent 修改了代码、配置、脚本、测试或治理文档，准备向用户报告结果。
- 一个 backlog story 或 iteration 准备进入 `Done` / `Closed`。
- 用户要求提交、推送、发布或检查外部实施结果。
- Navigator、质量审查或故障排查发现“实现存在，但状态/证据/后续处理缺失”。

纯查询、只读分析或尚未获准实施的方案讨论不要求创建闭环记录，但最终回复仍应明确
没有实施变更。

本规则从 EVO-038 / Iteration 015 起适用于新实施任务。历史已关闭 iteration 不因
缺少新模板字段而被机械判错；复核历史工作时如发现真实状态、验证或残余追踪缺陷，
应登记修复故事并按本文完成补救。

## 完成声明规则

实施任务必须使用以下结论之一：

| 结论 | 可使用条件 |
|------|------------|
| `Complete` | 授权范围内产物完成；适用状态归口已同步；所需验证已执行并记录真实结果；已知残余已登记或明确不在范围内。 |
| `Partial` | 已形成有用产物，但仍缺状态同步、必需验证、残余登记或授权范围内的实现步骤。 |
| `Blocked` | 缺少权限、用户决策、必要源文件、外部条件或失败前置门禁，无法合法继续并完成。 |

不得以“文件已经改好”“大部分完成”“应当可用”替代上述判断。验证失败或未执行的
必需门禁、未同步的 backlog/iteration、只停留在对话中的已知残余，都会阻止
`Complete`。

## 闭环台账

开始实施前，在当前 iteration 或可追溯工作记录中填写：

```markdown
| 项目 | 本轮记录 |
|------|----------|
| 请求结果 | 用户最终需要得到什么 |
| 产物 | 将创建或修改哪些代码/文档/配置 |
| 状态同步归口 | backlog / iteration / contract / ADR / EVOLUTION / release notes 中适用项 |
| 验证证据 | 按风险需要执行的命令或人工检查 |
| 残余工作归口 | 未完成项、失败门禁或刻意延后内容写到哪里 |
```

非迭代紧急修复允许先止血，随后在同一会话将台账补入 backlog/iteration 或修复记录。

## 操作步骤

### 1. 建账

1. 读取 `git status --short --branch` 和任务路由要求的 SOP。
2. 确认当前授权范围、需要保护的已有改动和最小可交付切片。
3. 新需求、缺陷或技术债先写 backlog；已启动 story 的范围变化走
   [迭代中需求变更](CHANGE-CONTROL.md)。
4. 写入闭环台账，特别标清状态同步与残余工作归口。

### 2. 实施

1. 只实现台账列出的切片。
2. 发生目标变化时暂停扩大改动，更新台账并执行变更控制。
3. 修改脚本、合约、稳定事实或重大取舍时，写入其专属归口文档。

### 3. 核验

1. 按 [测试与验证](TESTING.md) 或任务专属 SOP 运行风险匹配的检查。
2. 文档治理改动至少执行 [文档一致性检查](DOC-CHECK.md) 中的链接与 diff 检查。
3. 在 iteration / backlog 验收记录中写真实命令及结果。
4. 失败或未运行的必需检查不得勾选通过；应修复、降为 `Partial` 或登记阻塞。

### 4. 同步

逐项确认是否适用并更新：

- backlog 总表、详情块和验收标准；
- iteration 执行记录、Review、Retrospective 和状态；
- 依赖、阻塞、计划改线或 Epic 子项汇总；
- API contract、Reference、ADR、Roadmap 或 Proposal 替代关系；
- `EVOLUTION.md` 的新经验和 `SCRIPTS-RELEASE-NOTES.md` 的脚本行为变化；
- 提交/推送请求所需的 Git 状态和 staged diff。

不适用的项目不需要制造空文档；但在收口结论中说明其不适用原因。

### 5. 交付

最终回复或 iteration Review 至少包含：

```markdown
闭环状态：Complete / Partial / Blocked
已实施：
已同步：
已验证：
残余：
```

如为 `Partial` 或 `Blocked`，残余项必须明确归口文档或等待条件，不得仅写“后续处理”。

## 防呆检查表

- [ ] 已有闭环台账，且授权范围与产物一致。
- [ ] 新问题已进 backlog 或已说明无需新增记录。
- [ ] 实际状态与 backlog / iteration / Epic 依赖记录一致。
- [ ] 必需验证有实际结果，不以预期或历史结果替代。
- [ ] 已知残余、失败门禁或延期内容有明确归口。
- [ ] 经验、ADR、合约、脚本 release note 等专属归口已按需更新。
- [ ] 最终完成声明与上述证据一致。

## 失败处理

- 已实施但没有台账：暂停扩大修改，补记当前范围、验证和状态归口后再收尾。
- 已标 `Done` 但缺证据或状态同步：改回 `Review` 或登记修复事项，补齐前不得报告
  `Complete`。
- 发现残余但不属于当前范围：在 backlog/iteration 中登记归口，再报告当前切片结果。
- 权限或用户决策阻塞：保留已验证产物，列明等待条件，结论使用 `Blocked`。
